# Запуск на RTX 2070 8 GB

Все YAML-пайплайны используют рабочий batch 8. Накопление градиентов сохраняет
эффективный batch: 8 × 32 = 256 для main, EVE-PE и depth-experiments;
8 × 4 = 32 для RELU_SWIGLU. Число eval_iters увеличено пропорционально, чтобы
сохранить количество оцениваемых примеров. Архитектуры, длины, seeds и LR сохранены.
Порядок группировки примеров и округление изменились, поэтому результаты могут отличаться.

`hardware.dtype: auto` выбирает FP16 с GradScaler на RTX 2070, нативный BF16
на поддерживающих GPU и FP32 на CPU. В depth-experiments сохранён явно заданный
FP32. `torch.compile` отключён. Реализация масштабирования следует
[рекомендациям PyTorch AMP](https://docs.pytorch.org/docs/stable/notes/amp_examples.html).

```powershell
python -B -u main.py
python -B -u main.py --config configs/EVE-PE/pe_lab.yaml
python -B -u main.py --config configs/RELU_SWIGLU/ffn.yaml
python -B -u main.py --config configs/depth-experiments/perm_depth.yaml
python -B -u PE_EXP/run.py
```

Для новых YAML-экспериментов рядом со старыми результатами задайте отдельный
`--set paths.run_dir=runs/rtx2070/имя_эксперимента`. PE_EXP по умолчанию использует
новый каталог `PE_EXP/results/rtx2070`; повтор той же команды продолжает его.

`evaluate.py` и `probe.py` по умолчанию обрабатывают по 8 примеров. Для checkpoint,
сохранённого с явным BF16 на другой GPU, укажите `--dtype auto`.
Если конкретной конфигурации не хватает памяти, уменьшите YAML batch до 4 и
удвойте gradient_accumulation_steps и eval_iters. В PE_EXP уменьшение microbatch
при CUDA OOM происходит автоматически, вплоть до одного примера.

Проверки:

```powershell
python -B main.py --config configs/EVE-PE/pe_lab.yaml --dry-run
python -B PE_EXP/run.py --dry-run
python -B PE_EXP/verify.py
```

Настройки рассчитаны на небольшой рабочий batch, но пиковая VRAM и скорость
на RTX 2070 не измерены. Локальная проверка FP16 выполнена на GTX 1050 4 GB;
полная матрица обучения не запускалась.
